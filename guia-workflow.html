ContaERP — Guía de Workflow

Cómo trabajar con VS Code, GitHub, Vercel y Railway

Las 3 plataformas

🐙

GitHub

Almacena el código. Cada git push dispara el deploy automático en Vercel y Railway.

github.com/GmarkSA
▲

Vercel

Hospeda el Frontend (React). Se actualiza solo cuando haces push al branch master del frontend.

gllapp.vercel.app
🚂

Railway

Hospeda el Backend (NestJS) y la base de datos PostgreSQL. Se actualiza solo con cada push al backend.

contaerp-backend-production.up.railway.app

📋 Flujo de trabajo diario desde VS Code

1

Abrir VS Code

Abre la carpeta del proyecto que vayas a modificar:
Frontend: C:\Users\l_cha\contaerp-frontend
Backend: C:\Users\l_cha\contaerp-backend

2

Iniciar servidores locales (para desarrollo)

Abre dos terminales en VS Code (Ctrl + `):

cd contaerp-frontend && npm run dev
cd contaerp-backend && npm run start:dev

Frontend local en http://localhost:5173 | Backend local en http://localhost:3000

3

Hacer cambios en el código

Edita los archivos normalmente en VS Code. Los cambios se reflejan en tiempo real en el navegador (hot reload).

4

Verificar que no hay errores

Antes de subir, verifica tipos TypeScript:

npm run typecheck
5

Subir cambios a GitHub → Deploy automático

Desde la terminal de VS Code o desde el panel Git de VS Code:

git add .
git commit -m "descripción del cambio"
git push

✅ Vercel detecta el push del frontend y despliega en ~1 min
✅ Railway detecta el push del backend y despliega en ~3 min

6

Verificar en producción

Entra a gllapp.vercel.app y verifica que los cambios estén activos.

⭐ La regla de oro

Desarrollas local → Verificas → git push → Producción se actualiza sola

Nunca necesitas entrar a Vercel o Railway para desplegar.
Solo necesitas entrar si hay un error que quieres diagnosticar en los logs.

⚠️ Cosas importantes a recordar

Variables de entorno en Railway: Railway v2 no inyecta variables custom en el contenedor. Las credenciales de BD están hardcodeadas en database.config.ts con los valores internos de Railway. No cambies la contraseña de PostgreSQL en Railway sin actualizar el código también.
Base de datos de producción: Los cambios en las entidades TypeORM ya no se aplican automáticamente (synchronize: false). Si agregas nuevas columnas o tablas, deberás ejecutar el SQL manualmente en Railway → PostgreSQL → Data.
Secretos JWT: Los secretos JWT tienen valores por defecto en el código (app.config.ts). Si algún día quieres cambiarlos, todos los usuarios deberán volver a iniciar sesión.
Frontend en Vercel: Si cambias la URL del backend, debes actualizar VITE_API_URL en Vercel → Settings → Environment Variables y hacer Redeploy.
